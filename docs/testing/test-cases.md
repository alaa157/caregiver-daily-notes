# Android local-accounts test catalog

Scope: LOCAL_MODE local accounts on `feat/standalone-byok-ai`. Test IDs in this
catalog are referenced by `traceability-matrix.md`; the proving tests are the
real JVM/instrumented tests under `android/app/src/test` and
`android/app/src/androidTest`.

| Test ID | Covers | Description | Preconditions | Steps | Expected result |
|---|---|---|---|---|---|
| TC-ACC-001 | #606 | Create a local account with display name, email, and password. | Fresh `accounts.db`; no active account. | Submit the register form with a valid name/email/password. | A credential-free `Account` is created, password material is not exposed, and the new account becomes active. |
| TC-ACC-002 | #606 | Sign in with a normalized email and reject bad credentials. | Account exists with known password. | Sign in with case/space variants of the email; then with wrong/unknown credentials. | Correct password signs in and updates `lastUsedAt`; wrong/unknown credentials fail without touching the row/session and use the same error shape. |
| TC-SEC-001 | #605 | Hash and verify passwords with salted PBKDF2 and policy checks. | Password hasher/policy available. | Hash the same password repeatedly; verify correct/wrong passwords; check policy boundaries and constant-time comparison guards. | Salts/hashes differ per hash, stored iterations are honored, policy rejects weak passwords, and no insecure comparison/logging exists. |
| TC-ISO-001 | #627 | Keep care data isolated per account database. | Two accounts with seeded data. | Write/read through account A and B; switch back to A; query home/history/search/summary/plans. | Each account sees only its own `notes-<accountId>.db` rows; switching back restores A intact and no cross-account rows appear. |
| TC-ISO-002 | #627 | Scope preferences/onboarding to the account where required. | Two accounts; global language/theme set. | Complete onboarding/preferences under A; inspect B; switch language/theme. | Account-scoped preferences/onboarding are absent for B; language/theme remain global and unchanged by account switch. |
| TC-SW-001 | #628 | Switch between accounts without leaking state. | Accounts A and B exist; A active. | Switch to B, then back to A; attempt no-op/missing-id switches. | Provider swap order is cancel/join/close/persist/open; current account is unchanged for no-op/missing id; in-flight account work is cancelled. |
| TC-RM-001 | #628 | Remove a non-active account after confirmation. | Accounts A and B exist; B active. | Open remove dialog for A; cancel, then confirm; try removing active B. | Cancel does nothing; confirm calls removal once and deletes A's row/db/keys/exports; active account cannot be removed and failure keeps the dialog open with localized error. |
| TC-AI-001 | #629 | Scope AI keys/settings per account. | Accounts A and B; provider keys configured. | Store different keys for A/B; switch accounts; delete A; create C. | B cannot read A's key, aliases contain account id, provider/model/baseUrl/consent are per account, deletion removes only that account's keys, and new accounts see defaults. |
| TC-BKP-001 | #630 | Backup/restore stays inside the active account. | Accounts A and B with distinct data. | Create backup as A; attempt restore into B; restore into A. | Backup captures only A's records; restore into the wrong account is rejected; committing replaces A's local data and refuses stale/conflicting previews. |
| TC-CSV-001 | #630 | CSV export/import writes only the active account. | Accounts A and B; notes in both. | Export CSV as A; import into B and into A; resolve unmatched recipients. | Export contains only A rows; import writes only into the active account; planner counts duplicates/invalid/skipped rows and resolves recipient mappings explicitly. |
| TC-PD-001 | #631 | Restore session/account state after process death or restart. | Account session and per-account DB exist. | Kill/recreate the process or store; restart with stale/removed active id; interrupt a switch. | Active account restores from the persisted id, removed accounts do not reappear, stale ids do not crash, and a half-completed switch cannot point at a closed database. |
| TC-UI-001 | #632 | Account screens are localized and RTL-correct in EN/AR. | Locale can be set per test. | Render sign-in/register/picker/settings/remove/add/claim screens in English and Arabic. | English shows LTR labels; Arabic shows RTL layout direction and localized copy, active marker, disabled remove explanation, and dialog labels. |
| TC-MIG-001 | #626 | Claim legacy `caregiver-db` data into a new owner account. | Legacy `caregiver-db` exists; no accounts/active account. | Launch upgrade path; attempt back/dismissal; create owner account; retry migration. | Detector is read-only and reports `NeedsClaim`; claim screen blocks workspace and Back; failed creation stays on screen; success hands off to migration; legacy data becomes readable only under the owner account and repeat runs are no-ops. |
