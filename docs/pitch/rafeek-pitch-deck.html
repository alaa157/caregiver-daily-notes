The problem

Care is continuous.
Documentation often isn't.

  1. Observations scatter. Notebooks, chat threads, and memory each hold a piece of the day.
  2. Context disappears between caregivers. What the morning shift knew, the evening shift re-discovers.
  3. Inconsistent entries make history hard to review. No structure means no reliable comparison across days.
  4. Small signals are hard to connect across time. Three poor-appetite days matter — if anyone can see all three.
  5. Structure can't cost the human context. Caregivers need fields, but also their own words.

Ebrahim AhmedBackend engineering09 / 15
BACKEND — 0:50. "Eight domains share one API surface, and every request passes the same gauntlet: validation, JWT authentication, then owner-scoped queries. A detail we're proud of because it's a security decision: if you request another caregiver's resource, you get 404 — not 403. A 403 would confirm the record exists; a 404 reveals nothing. Writes carry an Idempotency-Key: retrying a save replays the original result instead of duplicating it, and a genuine conflict returns 409. That's what makes the 'safe retry' in the UI honest — the backend guarantees it. Errors follow one unified contract, migrations are versioned V1 to V17, and every meaningful action lands in an append-only audit log with secret redaction. These aren't aspirations; each one has dedicated tests you'll see in the evidence." TERM: idempotency = performing the same request twice has the same effect as once. TAKEAWAY: The contract is the product — retries are safe, ownership is invisible, history is provable. Engineering · integrity & safety

Trust must be built into the system.

The record — append-only

The model's boundary

CAN

  • Raise urgency
  • Ground claims in source notes
  • Suggest catalog actions
  • Surface uncertainty

CANNOT

  • Suppress a deterministic flag
  • Add, remove or alter medications
  • Invent actions outside the catalog
  • Decide for the caregiver
Safety signals and trends are computed by ordinary backend code — never delegated to the language model. Accept, edit, or dismiss stays human.
Ebrahim AhmedIntegrity & safety10 / 15
INTEGRITY & SAFETY — 1:10. "This is the slide I'd ask you to remember from the engineering section. Left: how a record lives. The original note is immutable. Corrections arrive as addenda or typed events — set a value, clear it, mark it unknown, mark it not recorded — and the effective state you see is a deterministic replay of the original plus every event. Anyone can reconstruct what was known, when, and by whom. Right: the model's leash. Red flags — a fall, high pain, repeated missed medication — are computed by ordinary code, before and independently of any LLM. The model may raise urgency; it can never lower or remove a flag, never touch medication names, doses or schedules, and plan actions come from a fixed catalog: check-ins, meal reminders, mobility goals, education, contact a doctor. Every claim must quote a real source note. And the final decision — accept, edit, dismiss — belongs to the caregiver. We say it in one line: the model never holds the pen on safety."
