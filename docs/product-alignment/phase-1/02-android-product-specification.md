# Android product specification (functional reference)

**Reference:** `feat/standalone-byok-ai` at `21876285ad808a6518593ea3974c51b6b1f6bb31`. This is based on implementation, not README-only claims. Android's offline-first behavior and user-controlled BYOK are product constraints.

## Navigation and screens

The app declares 23 Navigation destinations plus a root onboarding flow: sign in, register, server URL (server-mode paths); Home, People, Notes, History tabs; recipient detail/create; note editor/saved/detail/addendum; summary period/result; plans/proposal/edit/versions; Settings, AI settings, theme colors, About. The four bottom tabs are explicitly listed in [`Routes.kt`](https://github.com/alaa157/caregiver-daily-notes/blob/2187628/android/app/src/main/java/com/caregiver/mobile/core/navigation/Routes.kt#L11-L74). Main navigation and drawer actions live in `MainScaffold.kt`; login/server configuration is skipped when `LOCAL_MODE` is true. `CareTrendsScreen.kt` is an additional composable, but no navigation registration or call site was found: treat it as an unreachable placeholder, not a usable screen.

## Important rules and failure behavior

- Local recipient deletion is destructive after archive; it is not the backend's soft-deactivation operation. Do not equate the two.
- The standalone local database has a different schema and nullability from backend notes. Current local note fields are not a wire-contract guarantee.
- Notes/addenda are treated as immutable history; corrections are appended. Backups preserve stable string IDs and relationships.
- Summary AI is untrusted. Android limits observations, scopes source notes to recipient/date range, verifies cited quote presence and lexical support, and retains deterministic flags on provider failures.
- AI data is sent directly from the phone only after provider-specific consent. Key absence leaves notes usable; it does not create a model summary.
- This is care-support software, not a medical device or validated clinical decision system.

Android contains dedicated tests for navigation, recipients, note editor, history, summary, plans, medication, migration, backup, CSV, and API DTOs (for example `android/app/src/test/.../ApiContractTest.kt`, `.../SummaryAiServiceTest.kt`, `.../MedicationStoreTest.kt`; UI tests include `OfflineDemoFlowUiTest.kt`).
