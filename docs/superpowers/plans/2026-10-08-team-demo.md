# Team demo plan — fonts in-app, demo data, install via GitHub Releases

Goal: a team member installs the APK from a GitHub Release on their phone,
points it at the demo backend, and sees the app looking like
`/workspaces/android_rtl.html` with realistic data. No system/font
installation on any phone; no Play Store.

Constraints (from user):
- Fonts ship **inside the APK** (`res/font`), never installed on the phone,
  no downloadable-fonts provider (no Play-Services / first-launch internet dependency).
- Install path is **GitHub Releases** (`gh release download` / phone browser).
- LLM keys already exist as **repo secrets** — plan wires them to runtime (see §3).
- Branch: everything below lands on `preview/full-stack` only. Never `main`.

## 0. Where the keys go (read this first)

The backend reads keys from **process environment variables at runtime**
(`backend/src/main/resources/application.yml`):

| Variable | application.yml | Required? |
|---|---|---|
| `JWT_SECRET` | line 5, `${JWT_SECRET}` (no default — boot fails without it) | yes |
| `GEMINI_API_KEY` | line 55, `${GEMINI_API_KEY:}` (empty = Gemini skipped) | for smart summary |
| `OPENROUTER_API_KEY` | line 52, `${OPENROUTER_API_KEY:}` (empty = backup skipped) | for summary failover |
| `DATABASE_URL/USERNAME/PASSWORD`, `REDIS_URL` | datasource/redis blocks | yes, to boot at all |

Repo secrets (`gh secret list`) are **build-time only** — GitHub Actions cannot
inject them into your laptop's backend process. For the demo you run the
backend yourself, so export them in the same shell that starts it:

```bash
export JWT_SECRET="$(gh secret view JWT_SECRET 2>/dev/null || echo PASTE_ME)"
export GEMINI_API_KEY="$(gh secret view GEMINI_API_KEY 2>/dev/null || echo PASTE_ME)"
export OPENROUTER_API_KEY="$(gh secret view OPENROUTER_API_KEY 2>/dev/null || echo PASTE_ME)"
export DATABASE_URL=... DATABASE_USERNAME=... DATABASE_PASSWORD=... REDIS_URL=...
# then start the backend + tunnel (see §4)
```

(`gh secret view` needs admin; otherwise copy values from
GitHub → repo Settings → Secrets and paste.) If the backend ever moves to
Render, the same names go in the Render dashboard → service → Environment tab.

## 1. Bundled Arabic font (in the APK, not the phone)

Design boards use **IBM Plex Sans Arabic** weights **400 / 500 / 700**
(verified by scanning board CSS). The app currently uses the system default
(`Type.kt` = bare `Typography()`).

Steps:
1. Download the three static TTFs (OFL-licensed, free to bundle):
   `IBMPlexSansArabic-Regular.ttf`, `-Medium.ttf`, `-Bold.ttf`
   (Google Fonts repo, `ofl/ibmsansarabic/`).
2. Put them in `android/app/src/main/res/font/` as
   `plex_arabic_regular.ttf`, `plex_arabic_medium.ttf`, `plex_arabic_bold.ttf`
   (lowercase, underscores — aapt requirement).
3. In `core/theme/Type.kt`: build `val PlexArabic = FontFamily(Font(R.font.plex_arabic_regular), Font(R.font.plex_arabic_medium, FontWeight.Medium), Font(R.font.plex_arabic_bold, FontWeight.Bold))` and set `defaultFontFamily = PlexArabic` on `AppTypography` (copy of `Typography()` with the family applied to every scale — one place, all screens change).
4. Latin glyphs inside Plex Arabic render fine, so English mode needs no second family.
5. Verify: `./gradlew :app:testDebugUnitTest` (add/extend a unit test asserting `AppTypography.bodyLarge.fontFamily == PlexArabic`), `lintDebug`, and one screenshot on device.
- Size impact ≈ +0.5 MB. No new permissions, no internet needed for text.
- Do NOT use the downloadable-fonts API (`com.google.android.gms.fonts`) — rejected per constraints.

## 3. Demo seed data (script, not migration)

A SQL migration would ship demo rows into every future database — rejected.
Instead `docs/demo/seed-demo.sh` (curl against the running backend):

1. `POST /api/auth/register` → demo caregiver (e.g. `demo@caregiver.app` /
   `Demo1234!`) and save the token.
2. `POST /api/recipients` × 2 (one named `محمد أحمد` to mirror board 3).
3. `POST /api/notes` × 4–5 across both recipients, one containing a fall
   mention (lights up the home safety banner) and one with an unclear-medication
   line (lights up the summary red-flag path).
4. `POST /api/notes/{id}/addenda` × 1 (shows an addendum in detail/history).
5. `POST /api/plans` × 1 accepted plan (fills plan screens + versions).
6. Print the demo login + server URL at the end for the presenter.

Script is idempotent-ish (fixed demo email; re-running creates dupes — note it,
or add a `--reset` that deletes the demo caregiver's rows first). Keep the
script on `preview/full-stack` only.

## 4. Release APK on GitHub Releases (what you install from)

`.github/workflows/android.yml` today uploads APKs as **workflow artifacts**
only — phones can't install those. Add a `release-apk` job (or extend
`build-debug`): on a pushed tag `demo-v*`, download the `android-debug-apk`
artifact and publish with `softprops/action-gh-release@v2` (`files:
app-debug.apk`, `generate_release_notes: true`, `prerelease: true`).

Release flow:
```bash
git tag demo-v0.1.0 && git push origin demo-v0.1.0   # CI builds + publishes
gh release download demo-v0.1.0 -p '*.apk'           # or phone browser → repo → Releases
```
- Ship the **debug** APK (`app-debug.apk`, ~12 MB): installs with an
  "unknown sources" prompt, no signing setup. The `minified` APK stays
  experimental until R8 is smoke-tested on device.
- `minSdk 21`, one universal APK — no per-ABI choice needed.

## 5. Demo-day runtime (backend + phone)

1. Laptop: export keys (§0), start backend (`./mvnw spring-boot:run` or the
   project's run command), start tunnel:
   `cloudflared tunnel --url http://localhost:8080` → copy the
   `https://…trycloudflare.com` URL.
2. Run `docs/demo/seed-demo.sh <tunnel-url>` once.
3. Phone: install APK from the GitHub Release, open app → server-URL screen →
   paste tunnel URL → login as the demo caregiver → demo in Arabic, toggle to
   English for the finale.
4. Keep the laptop awake + tunnel alive for the whole demo (tunnel URL dies
   with the process; if it restarts, re-paste the new URL in the app — no
   reinstall needed).

## 6. Suggested 10-minute demo script (board order)

Login → Home (fall banner) → People → محمد أحمد detail → ملاحظة اليوم
editor → تم الحفظ → note detail → addendum → السجل + filters → الملخص الذكي

language toggle to English → Home again.
