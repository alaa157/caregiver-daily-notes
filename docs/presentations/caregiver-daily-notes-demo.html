Caregiver Daily Notes1
The problem

A carer remembers what they can, and forgets the rest

  • The day is the record. Mood, appetite, sleep, mobility, pain, a fall, medication taken — and it has to be written down before it is forgotten.
  • One carer, many people. Each person has their own history, and nobody else's.
  • The dangerous details are the scattered ones. A fall, a missed dose, a pain that climbed — that is what needs surfacing, not everything else.
  • The handover is a phone call. Whoever is on shift next needs the week, not the last three hours.

The app

Five tabs, one workflow

Home→ People→ Add a note→ History→ Summary & plan
  • Home — today at a glance, what needs attention, and the day's medication marks.
  • People — who is in your care, and the detail behind each person.
  • Notes — structured chips plus free text, in Arabic, English or mixed. Append-only: corrections are addenda, never overwrites.
  • History — filter by person and date; share a PDF summary.
  • Summary — 7 / 14 / 30 days, grounded in the notes, with the safety flags that never go away.

The app3
What it does

The parts that matter

01

One caregiver role

Strict ownership. Each carer sees only their own people — enforced on the server, not just hidden in the UI.

02

Notes that cannot be quietly rewritten

Append-only with addenda. The record of what was observed stays intact.

03

Grounded summaries

Every claim cites a note and quotes it verbatim. Unsourced claims are dropped, not softened.

04

Deterministic safety flags

Falls, high pain, missed medication, poor appetite. The model can raise urgency — never lower it.

05

Care plans from a fixed catalog

The model may only select actions that already exist. No invented steps, no prescriptions, ever.

06

Arabic and English, both first-class

The same workflows in العربية and English, with real RTL layout and mixed-direction names and quotes.

Highlights4
The hard part

An AI that cannot be talked into being wrong

Deterministic

Flags never come from the model

Falls, pain, missed medication and appetite streaks are computed from the data. The LLM can add urgency; it cannot remove a flag.

Grounded

Every claim quotes its note

A claim survives only if it cites a note that exists and the quote is verbatim. “Had pain” cited against “had no pain” is rejected.

Locked

Medication is a hard lock

Any AI-proposed medication change — in the payload or hidden in the prose — is rejected outright.

Fail-safe

A timeout is not a failure of the user

Timeouts, backoff and one repair retry, then an explicit “AI unavailable”. Saving a note never depends on the AI.

AI safety5
Architecture

Thin clients, one source of truth

Web
React + TS Android
Kotlin + Compose → Spring Boot API
Java 21 · JWT → Supabase Postgres
source of truth
  • The server owns the rules. Auth, ownership, validators, versioning and audit live server-side; the clients are thin.
  • One API, two clients. No shared frontend code, no second database.
  • The provider is swappable. The LLM sits behind an interface — model and provider can change without touching app logic.

Bring your own key

The caregiver supplies their own provider key. It is encrypted with a hardware-backed keystore key and never leaves the device except to authenticate with the provider it belongs to.

Architecture6
In the field

Built for a carer with one hand and a weak signal

RTL first

العربية is not a translation

The Arabic UI is laid out right-to-left, with mixed Arabic/English names and quotes correctly isolated inside the text.

Offline

Airplane mode is a normal state

Notes are written to a local database first and queued in an outbox. The caregiver keeps a draft and is told the truth about what has not synced yet.

The demo build ships with canned data and no backend, so it can be installed and clicked through on a plane — or in a demo with no network at all.

In the field7
Under the hood

The AI layer is built to fail quietly

Providers

OpenAI-compatible, Gemini, Anthropic, xAI, OpenRouter

One interface, native JSON mode where the provider offers it, and a fallback chain that ends in an explicit “AI unavailable” rather than a blank screen.

Repairs

One retry, then give up

A reply that is not readable JSON gets exactly one repair attempt — then the app says so instead of pretending.

Safety blocks

A blocked request is an answer, not an error

Notes about falls and pain can trip a provider's safety filter. That is reported as blocked, once, with no retry storm.

Evidence

Claims are checked against the quote

Term overlap plus a negation check, in both directions: a claim cannot drop a negation the quote carries, and a one-word quote proves nothing.

Try it

Six minutes, on any device

  • Install the debug APK from the CI artifact — arm64 device or x86 emulator.
  • Home greets you by name, and the layout mirrors in Arabic.
  • People → add a person with an Arabic name and an English name.
  • Add a note — chips, pain 0–10, save.
  • Summary → 7 days — the safety banner stays put through rotation and retry, and has no close button.
  • Airplane mode — the note is kept as a draft and the truth is reported.
